Ability Animation Reference: ground_slam

Complete implementation guide for one ability — covering design intent, sprite frames, JavaScript code, and system integration. Use this as the template for all 22 abilities.

0 What is ground_slam?

Used by: Stone Guardian (primary), Stone Lurker (primary), Obsidian Golem (primary)

Shape: Circle, radius 3 tiles from enemy center

Damage: 30 base (scaled by tier)

Telegraph: 1000ms (1 second — the player has one full second to react)

Recovery: 800ms (the punish window after the slam lands)

Cooldown: 5000ms

Effect: Screen shake on impact

The player experience: You see a growing orange circle on the ground. You have one second to walk or dodge out of it. If you don't, you take heavy damage and the screen shakes. After it lands, the enemy is briefly vulnerable — that's your window to hit back.

1 The Animation Lifecycle

Every ability in the game follows this exact four-phase lifecycle. The animation system needs to know which phase it's in and what to draw during each one.

TELEGRAPH
1000ms
HIT
instant
RECOVERY

TELEGRAPH What the player sees (1000ms)

  • An orange circle appears on the ground, centered on the enemy
  • The circle starts small and grows to full radius over 1 second
  • The circle's edge pulses to draw attention
  • The enemy plays a "raise arms" windup animation
  • A low rumble sound builds in volume

This is the warning. The player must decide: dodge out, or commit to staying close for damage.

RESOLVE What happens on impact (instant)

  • The growing circle flashes white for 1 frame then disappears
  • Concentric expanding rings burst outward from center
  • Small rock debris particles fly up and fall down
  • The screen shakes (4px offset, 200ms duration)
  • A heavy impact sound plays
  • Damage is applied to all players within the radius

RECOVERY The punish window (800ms)

  • The enemy plays a "stagger" animation — slightly hunched, off-balance
  • Faint dust particles linger around impact zone
  • Enemy takes 1.25x damage during this window
  • Enemy cannot move or start another ability

This is the player's reward for dodging. Rush in and deal damage before the enemy recovers.

IDLE Cooldown period (~3200ms)

  • No animation effect — the enemy is back to normal behavior
  • Enemy repositions (AI takes over)
  • Cooldown ticks down in the background
  • When cooldown reaches 0, the cycle can begin again

3 Sprite Frames (What to Draw)

These are the individual frames the animation system draws. Each frame is a small pixel grid rendered at game scale. For ground_slam, there are three visual components that play at different times:

A. Telegraph Frames (ground indicator — drawn below all entities)

A growing circle on the floor. 4 key frames over 1000ms. The circle starts at 30% radius and grows to 100%.

B. Impact Frames (the slam effect — drawn above the enemy)

Expanding concentric rings that burst outward. 6 frames, plays once on resolve.

C. Particle Frames (debris — drawn above everything)

Small rock chunks that fly upward then fall. Each particle has its own arc trajectory. 8-12 particles, each using a 3x3 or 4x4 pixel sprite.

4 JavaScript Implementation

This is the actual code your team writes. It's split into three parts: the data (what the animation looks like), the controller (manages animation state), and the renderer (draws it on screen).

Part A — The Data: Define what ground_slam looks like

This goes in effect-sprites.js. It tells the system the shape, color, and timing of every visual component.

// ─── effect-sprites.js ───
// This defines WHAT the animation looks like.
// One entry per ability. Each ability has components
// (telegraph, impact, particles) with their own frames.

const ABILITY_EFFECTS = {

  ground_slam: {
    // ── TELEGRAPH: growing circle on the ground ──
    telegraph: {
      type: 'circle_grow',       // Shape type — the renderer knows how to draw this
      color: '#FFAA00',            // Orange fill
      borderColor: '#FF6B35',      // Darker orange border
      fillOpacity: 0.25,           // Semi-transparent fill so you can see through it
      borderWidth: 2,              // Pixel width of the border ring
      startScale: 0.3,             // Starts at 30% of full size
      endScale: 1.0,               // Grows to 100% over the telegraph duration
      pulseSpeed: 6,               // Border pulses 6 times per second (edge brightens/dims)
      radius: 3,                   // 3 tiles — this MUST match the ability's actual hit radius
    },

    // ── IMPACT: expanding rings when the slam lands ──
    impact: {
      type: 'ring_burst',
      rings: 3,                    // 3 concentric rings expand outward
      colors: ['#FFCC00', '#FFAA00', '#886644'],  // Inner ring brightest
      startRadius: 0,              // Rings start at center
      endRadius: 3.5,              // Expand slightly past the hit radius (visual overshoot)
      duration: 400,               // 400ms for rings to fully expand and fade
      ringWidth: 3,               // Pixel width of each ring
      fadeStart: 0.6,              // Rings start fading at 60% of duration
      screenShake: {              // Camera shake on impact
        intensity: 4,              // Max pixel offset
        duration: 200,             // 200ms of shaking
        decay: 'linear',           // Shake intensity decreases linearly
      }
    },

    // ── PARTICLES: rock debris flying up ──
    particles: {
      count: 10,                   // 10 rock chunks
      sprite: {                    // What each particle looks like
        width: 3, height: 3,
        pixels: ['.R.', 'RRR', '.R.'],  // Diamond shape
        palette: { 'R': '#AA8866' }     // Brown rock color
      },
      spawnRadius: 1.5,            // Particles spawn within 1.5 tiles of center
      velocity: {                  // How particles move
        xRange: [-60, 60],         // Random horizontal speed (pixels/sec)
        yRange: [-120, -60],       // Always upward initially
      },
      gravity: 300,                // Pixels/sec² — particles arc up then fall
      lifetime: 600,               // Each particle lives 600ms
      fadeOut: 0.5,                // Start fading at 50% of lifetime
    },

    // ── AUDIO CUES ──
    audio: {
      telegraph: 'sfx_rumble_build',    // Low rumble that builds during 1s windup
      impact: 'sfx_heavy_impact',       // Loud thud + crack on resolve
    }
  }
};
Why this format matters: Every field above maps directly to a rendering operation. Your renderer reads type: 'circle_grow' and knows to draw an expanding circle. It reads startScale: 0.3 and knows the circle begins at 30% size. The data is separate from the code that draws it — this means designers can tweak values (make the telegraph faster, change the color, add more particles) without touching renderer code.

Part B — The Controller: Manage animation state

This goes in effect-animator.js. It tracks which effects are active, what phase they're in, and how far through each phase they are.

// ─── effect-animator.js ───
// This manages the STATE of each active effect.
// It answers: "what phase is this effect in, and how far through?"

const EffectAnimator = {
  activeEffects: new Map(),  // effectId → effect state
  nextId: 0,

  /**
   * Start a new ground effect.
   * Called by EnemyAbilitySystem.createTelegraph()
   *
   * @param abilityId   - 'ground_slam', 'charge', etc.
   * @param x, y        - World position (center of the effect)
   * @param telegraphMs - How long the telegraph lasts (1000ms for ground_slam)
   * @param radius      - Hit radius in tiles
   * @returns effectId  - Use this to update or remove the effect later
   */
  startEffect(abilityId, x, y, telegraphMs, radius) {
    const id = this.nextId++;
    const config = ABILITY_EFFECTS[abilityId];

    if (!config) {
      console.warn(`No effect defined for ability: ${abilityId}`);
      return -1;
    }

    this.activeEffects.set(id, {
      id,
      abilityId,
      config,
      x, y,
      radius,

      // ── Phase tracking ──
      phase: 'telegraph',          // 'telegraph' | 'impact' | 'done'
      phaseTimer: 0,               // ms elapsed in current phase
      telegraphDuration: telegraphMs,

      // ── Particle state (created on impact) ──
      particles: [],
    });

    return id;
  },

  /**
   * Called every frame by the game loop.
   * Advances all active effects through their phases.
   */
  update(deltaTime) {
    for (const [id, effect] of this.activeEffects) {
      effect.phaseTimer += deltaTime;

      switch (effect.phase) {

        case 'telegraph':
          // Telegraph is done when the timer exceeds the duration.
          // NOTE: We don't transition automatically here!
          // The ability system calls resolve() when the ability lands.
          // This prevents the visual from desyncing from the gameplay.
          break;

        case 'impact':
          // Update particles (gravity, fade)
          this.updateParticles(effect, deltaTime);

          // Impact phase ends when rings have expanded AND particles are dead
          const ringsComplete = effect.phaseTimer >= effect.config.impact.duration;
          const particlesDead = effect.particles.every(p => p.life <= 0);

          if (ringsComplete && particlesDead) {
            effect.phase = 'done';
          }
          break;

        case 'done':
          this.activeEffects.delete(id);
          break;
      }
    }
  },

  /**
   * Called by EnemyAbilitySystem when the ability resolves (damage is dealt).
   * Transitions the effect from telegraph → impact.
   */
  resolve(effectId) {
    const effect = this.activeEffects.get(effectId);
    if (!effect) return;

    effect.phase = 'impact';
    effect.phaseTimer = 0;

    // Spawn particles at the moment of impact
    this.spawnParticles(effect);

    // Trigger screen shake
    if (effect.config.impact.screenShake) {
      Camera.shake(
        effect.config.impact.screenShake.intensity,
        effect.config.impact.screenShake.duration
      );
    }

    // Play impact sound
    if (effect.config.audio?.impact) {
      AudioManager.play(effect.config.audio.impact);
    }
  },

  /**
   * Called by EnemyAbilitySystem if the ability is interrupted
   * (enemy dies or is stunned during telegraph).
   * Removes the telegraph visual immediately.
   */
  cancel(effectId) {
    this.activeEffects.delete(effectId);
  },

  // ── Particle helpers ──

  spawnParticles(effect) {
    const cfg = effect.config.particles;
    if (!cfg) return;

    for (let i = 0; i < cfg.count; i++) {
      // Random position within spawn radius
      const angle = Math.random() * Math.PI * 2;
      const dist = Math.random() * cfg.spawnRadius * TILE_SIZE;

      effect.particles.push({
        x: effect.x + Math.cos(angle) * dist,
        y: effect.y + Math.sin(angle) * dist,
        vx: cfg.velocity.xRange[0] + Math.random() * (cfg.velocity.xRange[1] - cfg.velocity.xRange[0]),
        vy: cfg.velocity.yRange[0] + Math.random() * (cfg.velocity.yRange[1] - cfg.velocity.yRange[0]),
        life: cfg.lifetime,
        maxLife: cfg.lifetime,
        sprite: cfg.sprite,
      });
    }
  },

  updateParticles(effect, dt) {
    const gravity = effect.config.particles?.gravity || 300;
    for (const p of effect.particles) {
      if (p.life <= 0) continue;
      p.x += p.vx * (dt / 1000);
      p.y += p.vy * (dt / 1000);
      p.vy += gravity * (dt / 1000);   // Gravity pulls down
      p.life -= dt;
    }
  },
};

Part C — The Renderer: Draw it on screen

This goes in effect-renderer.js. It reads the current state from the controller and draws the correct visual.

// ─── effect-renderer.js ───
// This draws the active effects on the canvas.
// Called every frame by the main render loop.

const EffectRenderer = {

  /**
   * Draw all active effects.
   * Called by the main render loop TWICE per frame:
   *   1. drawGround() — before entities (telegraphs go under monsters/players)
   *   2. drawOverlay() — after entities (impacts/particles go on top)
   */

  drawGround(ctx, cameraX, cameraY) {
    for (const [id, effect] of EffectAnimator.activeEffects) {
      if (effect.phase === 'telegraph') {
        this.drawTelegraph(ctx, effect, cameraX, cameraY);
      }
    }
  },

  drawOverlay(ctx, cameraX, cameraY) {
    for (const [id, effect] of EffectAnimator.activeEffects) {
      if (effect.phase === 'impact') {
        this.drawImpact(ctx, effect, cameraX, cameraY);
        this.drawParticles(ctx, effect, cameraX, cameraY);
      }
    }
  },

  // ── TELEGRAPH: Growing circle ──
  drawTelegraph(ctx, effect, camX, camY) {
    const cfg = effect.config.telegraph;
    if (cfg.type !== 'circle_grow') return;  // Other shapes handled elsewhere

    // How far through the telegraph are we? 0.0 → 1.0
    const progress = Math.min(effect.phaseTimer / effect.telegraphDuration, 1.0);

    // Current radius: lerp from startScale to endScale
    const scale = cfg.startScale + (cfg.endScale - cfg.startScale) * progress;
    const radiusPx = cfg.radius * TILE_SIZE * scale;

    // Screen position
    const sx = effect.x - camX;
    const sy = effect.y - camY;

    // Pulsing border (sinusoidal brightness)
    const pulse = 0.5 + 0.5 * Math.sin(effect.phaseTimer / 1000 * cfg.pulseSpeed * Math.PI * 2);
    const borderAlpha = 0.5 + pulse * 0.5;

    // Draw filled circle
    ctx.save();
    ctx.globalAlpha = cfg.fillOpacity;
    ctx.fillStyle = cfg.color;
    ctx.beginPath();
    ctx.arc(sx, sy, radiusPx, 0, Math.PI * 2);
    ctx.fill();

    // Draw border ring
    ctx.globalAlpha = borderAlpha;
    ctx.strokeStyle = cfg.borderColor;
    ctx.lineWidth = cfg.borderWidth;
    ctx.stroke();
    ctx.restore();
  },

  // ── IMPACT: Expanding rings ──
  drawImpact(ctx, effect, camX, camY) {
    const cfg = effect.config.impact;
    if (cfg.type !== 'ring_burst') return;

    const progress = Math.min(effect.phaseTimer / cfg.duration, 1.0);
    const sx = effect.x - camX;
    const sy = effect.y - camY;

    // Fade out in the last portion
    const alpha = progress > cfg.fadeStart
      ? 1.0 - ((progress - cfg.fadeStart) / (1.0 - cfg.fadeStart))
      : 1.0;

    ctx.save();
    ctx.globalAlpha = alpha;

    // Draw each ring at a staggered progress (inner ring leads)
    for (let i = 0; i < cfg.rings; i++) {
      const ringDelay = i * 0.12;  // Each ring starts slightly later
      const ringProgress = Math.max(0, Math.min(1, (progress - ringDelay) / (1 - ringDelay)));

      const ringRadius = (cfg.startRadius + (cfg.endRadius - cfg.startRadius) * ringProgress) * TILE_SIZE;

      ctx.strokeStyle = cfg.colors[i] || cfg.colors[0];
      ctx.lineWidth = cfg.ringWidth * (1 - ringProgress * 0.5);  // Rings thin as they expand
      ctx.beginPath();
      ctx.arc(sx, sy, ringRadius, 0, Math.PI * 2);
      ctx.stroke();
    }

    ctx.restore();
  },

  // ── PARTICLES: Rock debris ──
  drawParticles(ctx, effect, camX, camY) {
    for (const p of effect.particles) {
      if (p.life <= 0) continue;

      const lifeRatio = p.life / p.maxLife;
      const fadeThreshold = effect.config.particles.fadeOut;
      const alpha = lifeRatio < fadeThreshold
        ? lifeRatio / fadeThreshold
        : 1.0;

      const sx = p.x - camX;
      const sy = p.y - camY;

      // Draw the tiny pixel sprite
      ctx.save();
      ctx.globalAlpha = alpha;
      this.drawPixelSprite(ctx, p.sprite, sx, sy, 2);  // scale=2
      ctx.restore();
    }
  },

  // ── Helper: draw a small pixel sprite at a position ──
  drawPixelSprite(ctx, sprite, x, y, scale) {
    const hw = (sprite.width * scale) / 2;
    const hh = (sprite.height * scale) / 2;

    for (let row = 0; row < sprite.pixels.length; row++) {
      for (let col = 0; col < sprite.pixels[row].length; col++) {
        const char = sprite.pixels[row][col];
        if (char === '.') continue;  // Transparent

        ctx.fillStyle = sprite.palette[char];
        ctx.fillRect(
          x - hw + col * scale,
          y - hh + row * scale,
          scale, scale
        );
      }
    }
  }
};

Part D — The Glue: Connect it to the ability system

This is where the animation system hooks into the ability lifecycle from the v2 implementation plan. These are modifications to the existing executeAbility() and resolveAbility() methods.

// ─── In enemy-ability-system.js ───
// Modified executeAbility() — adds effect creation

executeAbility(enemy, target, ability, abilitySet) {
  const telegraphTime = /* ... existing telegraph calculation ... */;
  const recoveryTime = ability.recoveryTime || 600;

  // Set cooldowns (existing)
  abilitySet.cooldowns[ability.id] = ability.cooldown;
  abilitySet.globalCooldown = 1000;

  // Lock enemy (existing)
  enemy.abilityState = 'telegraph';
  enemy.abilityLockout = true;

  // ════ NEW: Start the visual effect ════
  const effectId = EffectAnimator.startEffect(
    ability.id,                         // 'ground_slam'
    enemy.worldX, enemy.worldY,         // center position
    telegraphTime,                      // 1000ms
    ability.radius || 0                  // 3 tiles
  );

  // Store the effectId so we can resolve or cancel it later
  enemy._currentEffectId = effectId;

  // Play telegraph audio
  const effectConfig = ABILITY_EFFECTS[ability.id];
  if (effectConfig?.audio?.telegraph) {
    AudioManager.play(effectConfig.audio.telegraph);
  }

  // Delayed execution (existing, with safety checks)
  const enemyId = enemy.id;
  setTimeout(() => {
    if (!enemy || enemy.hp <= 0 || !this.enemyAbilities.has(enemyId)) {
      EffectAnimator.cancel(effectId);    // ← cancel the visual too
      this.cleanupAbilityState(enemy);
      return;
    }
    if (enemy.isStunned || enemy.isRooted) {
      EffectAnimator.cancel(effectId);    // ← cancel the visual too
      abilitySet.cooldowns[ability.id] = ability.cooldown * 0.5;
      this.enterRecovery(enemy, recoveryTime * 0.5, enemyId);
      return;
    }

    // ════ NEW: Resolve the visual effect (telegraph → impact) ════
    EffectAnimator.resolve(effectId);

    // Apply damage (existing)
    this.resolveAbility(enemy, target, ability);

    // Enter recovery (existing)
    this.enterRecovery(enemy, recoveryTime, enemyId);

  }, telegraphTime);
},
Critical: Notice how the visual effect (EffectAnimator) and the gameplay effect (resolveAbility) are triggered by the same setTimeout at the same moment. They must stay synchronized. If the visual resolves at a different time than the damage, the player will see the slam land but take damage early or late — which feels like a bug and destroys trust in the telegraph system.

5 How the Render Loop Calls It

Your main game loop needs two new lines — one to update effect state, one to draw effects at the right layer.

// ─── In your main game loop ───

update(deltaTime) {
  // ... existing game update code ...
  EnemyAbilitySystem.update(deltaTime);   // Updates cooldowns, passives
  EffectAnimator.update(deltaTime);        // ← NEW: Updates effect animations
}

render(ctx) {
  // 1. Draw floor tiles
  TileRenderer.draw(ctx);

  // 2. Draw telegraphs ON TOP of floor, BELOW entities
  EffectRenderer.drawGround(ctx, camera.x, camera.y);  // ← NEW

  // 3. Draw entities (monsters, players, items)
  EntityRenderer.draw(ctx);

  // 4. Draw impact effects and particles ON TOP of entities
  EffectRenderer.drawOverlay(ctx, camera.x, camera.y);  // ← NEW

  // 5. Draw UI (health bars, minimap, etc.)
  UIRenderer.draw(ctx);
}
Why two render calls? Telegraphs are drawn on the ground (under monsters) so they look like floor markings. Impact effects and particles are drawn on top so they feel like explosions happening above the action. This layering is what makes the animation feel grounded in the world rather than floating on top of it.

6 Adapting This Template for Other Abilities

Every ability follows the same pattern. The only things that change are the telegraph shape, the impact visual, and the particles. Here's how to adapt this template:

For other Circle abilities (stomp, heavy_slam, pounce):

Same circle_grow telegraph type. Change radius, color, and speed. stomp is smaller (r2) and faster. heavy_slam adds knockback arrows pointing outward from center.

For Cone abilities (fire_breath, frost_breath, poison_cloud):

New telegraph type: cone_grow. Instead of a circle, draw a pie-slice shape that grows from the enemy outward in a specific direction. Needs a direction parameter (angle toward target) and arcWidth (60° for fire, 75° for frost, 90° for poison). The renderer draws the cone aimed at where the target was when the telegraph started — it does NOT track the target during the telegraph.

For Line abilities (charge, lunge, void_beam):

New telegraph type: line_grow. A rectangle from the enemy toward the target. Needs width (w2 for charge, w1 for lunge) and length (r10 for charge, l3 for lunge). charge's line should pulse red because getting hit by it is devastating.

For Projectile abilities (web_shot, homing_orb, projectile_burst):

No ground telegraph — instead, the enemy plays a windup animation and the projectile itself is the visual. The projectile sprite travels through the world using position interpolation. homing_orb needs a tracking behavior in its update loop. projectile_burst spawns 3 projectiles at different angles.

For Teleport abilities (shadow_step, teleport_strike):

Two-part visual: a "vanish" puff at the enemy's current position, then an "appear" flash at the target position. The telegraph is nearly instant (200-500ms), so the visual emphasis is on the arrival, not the warning. Use purple/dark particles for the shadow theme.
